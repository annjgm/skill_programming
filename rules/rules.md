# 全國高級中等學校商業類學生技藝競賽【程式設計職種】專案規範

本規範定義「全國高級中等學校商業類學生技藝競賽【程式設計職種】試題與詳解專區」專案之目錄劃分、解題品質標準、部署防錯機制與資安原則。所有 AI 代理人與開發者皆須嚴格遵守。

---

## 一、 目錄結構與發布權責劃分

1. **靜態網站發布目錄嚴格隔離**：
   - 線上正式站台發布來源嚴格限定為 `netlify_deploy_site/`（相對於專案根目錄）。
   - 所有供瀏覽器加載之網頁結構（`index.html`）、樣式表（`style.css`）、前端互動腳本（`app.js`）與對外提供下載之靜態檔案（`files/`），均必須位於 `netlify_deploy_site/` 目錄下。
   - **專案根目錄嚴禁設為 Netlify 發布目錄**。根目錄保留為原始解題工作目錄、自動化推導腳本、總體文件與 AI 設定。

2. **跨主機路徑相容性**：
   - 專案程式碼與腳本嚴禁寫死絕對磁碟代號（如 `C:\` 或 `D:\`），一律採用動態相對路徑（例如 `os.path.dirname(os.path.abspath(__file__))`），確保於任何新主機或環境皆能隨插即用。

3. **試題與詳解雙向同步原則**：
   - 專案根目錄的各年度資料夾（`111 年度/`～`115 年度/`、`詳解專區/`）為原始 Markdown 詳解與試題來源。
   - 當原始詳解新增或更新時，若欲同步提供線上瀏覽與下載，必須同步複製至 `netlify_deploy_site/files/詳解專區/` 對應年度目錄。
   - **檔名命名規範**：模擬試題詳解於下載目錄必須標註年度前綴（例：`111年度01_Advanced模擬試題詳解.md`、`111年度02_Beginner模擬試題詳解.md`）。

## 二、 試題解答與題解撰寫品質規範

所有學科與術科題目之解題與解析產出，必須嚴格符合以下結構：

1. **三段式標準解題架構**：
   - **第一段：題目簡述與規格說明**：明確摘錄題目情境、輸入格式（I/O）、輸出格式與數值邊界限制。
   - **第二段：核心觀念說明**：深度剖析演算法核心、資料結構選用、時間複雜度（Big-O）與空間複雜度分析，並特別提示極端測資邊界陷阱。
   - **第三段：正確答案編碼簡析**：提供符合 Python 3 標準之參考程式碼，附帶關鍵行逐步拆解與語義說明。

2. **實作與效能最佳實踐**：
   - **巨量測資 I/O 優化**：面對大量或未指定筆數輸入，優先採用 `sys.stdin.read().split()` 批次解析，避免因逐行 `input()` 導致 TLE。
   - **大數運算規範**：善用 Python 原生之任意精度大整數特性，無需手寫高精度計算，但需注意浮點數精確度與 `-0.00` 格式化陷阱。
   - **極端邊界覆蓋**：解題時必須驗證 $N=0$、單一元素陣列、全負數數列、數值極大值等極端測資。

## 三、 部署前防錯驗證機制（Fail-Fast）

1. **強制執行本機連結完整性檢查**：
   - 每次修改 `netlify_deploy_site/index.html` 或調整資源檔案後，**在執行部署上傳前，強制執行驗證腳本**：
     ```powershell
     python verify_links.py
     ```
   - 必須確認輸出顯示 `[SUCCESS] All X files exist locally with valid sizes!`，且無任何缺失連結（43+ 檔案大小皆大於 0 位元組）。
   - 若存在任何缺失連結或 0 位元組檔案，**嚴禁執行部署**。

2. **Netlify 專案鎖定**：
   - 線上正式站台網址：`https://python-program-exam-resource.netlify.app/`
   - Netlify 專案 Site ID：`5d640b28-fc5d-474f-8dfc-59ef891e82c5`
   - 部署時必須明確指定上述 Site ID，嚴禁未經確認建立重複站台或覆蓋非目標專案。

3. **外連與檢視規範**：
   - 網站所有下載檔案按鈕必須配置 `target="_blank" rel="noopener noreferrer"`，確保使用者能另開視窗直接檢視 PDF 試題與 Markdown 內容，且不得配置阻礙預覽的強制下載屬性。

## 四、 資安、語系與版本維護

1. **認證資訊即用即銷**：
   - 部署所使用之 Netlify Personal Access Token 或臨時金鑰，嚴禁硬編碼進專案源代碼或提交至版本控制；部署完成後，相關暫存腳本必須立即徹底清除。
2. **核心資產保護**：
   - 所有輔助生成腳本（例如 `update_html.py`、`verify_links.py`）之最新版本均為專案關鍵資產，嚴禁任意刪除。
3. **語系與排版規範**：
   - 所有 Markdown 文件與 HTML 原始碼一律強制採用 `UTF-8` 無 BOM 編碼。
   - 繁體中文排版嚴格遵循台灣慣用語（例如：程式碼、陣列、走訪、遞迴、字串、快取），中英文字與數字之間維持半形空格。
